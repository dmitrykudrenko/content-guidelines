# Valuable Information — Concept

> Status: `DRAFT` — transferred from original document

Valuable information enhances understanding, solves problems, and aids decision-making. It's presented clearly to maximize usefulness. It cannot be something that ChatGPT generates without unique context — if AI can write it without our experience, it's not valuable content.

## 3 Types of Additional Valuable Information (AVI)

### 01 — Systematization (Problem Analysis)

Break down and organize the problem clearly. This step helps in understanding the issue deeply and sets the stage for finding solutions.

**Example:** Instead of "5 tips for email design" → systematize all approaches to email design into a framework with clear categories and selection criteria.

### 02 — Unique Knowledge (Solution Ideas)

Propose innovative solutions using unique insights. Offer new perspectives that can be tested. Learning comes from both successes and failures.

**Example:** Share results of our A/B tests, internal statistics, insights from working with customers — things no one else can know.

### 03 — Product Mastery (Implementation)

Apply and share how solutions work in practice. Document both what works and what doesn't — this guides others in practical application and learning.

**Example:** Step-by-step implementation of a solution through our product with real results, screenshots, and metrics.

## VI Levels in Content

Each content type requires a different level of Valuable Information:

| VI Level | What it means | Where it's used |
|----------|--------------|----------------|
| **0** | Basic content without AVI | Support docs, SEO articles, landing pages |
| **1** | At least 1 type of AVI | Guest posts, SEO, marketing |
| **2** | 2 types of AVI, deeper analysis | Industrial/marketing content |
| **3** | All 3 types of AVI, maximum depth | Product content, Big Idea, eBooks |

→ How levels map to content types: [04-content-types-and-formats.md](04-content-types-and-formats.md)

## Publication Order

Strategic order when creating a series of notes on one topic:

1. **Systematization** → define and classify the problem
2. **Unique Knowledge** → think about possible resolutions, test them (it's OK to be mistaken or fail — any work like this is worth publishing)
3. **Product Mastery** → share implementation and practical results

This order is logical: first we break down the problem, then we look for solutions, then we show the implementation.

## Author Checklist: "Does my content contain AVI?"

> Run this on your own draft before you hand it over. It takes 5 minutes.
> The rule of the checklist: if you can't point to a specific section, the AVI isn't there.

### Step 1 — What is required for this piece?

| Question | Where to find the answer |
|----------|-------------------------|
| What content type is this? | [04-content-types-and-formats.md](04-content-types-and-formats.md) |
| What VI level does that type require? | VI table above |
| How many AVI types must I prove? | Level 1 → one type. Level 2 → two. Level 3 → all three. |

### Step 2 — Two elimination tests

1. **The ChatGPT test.** Could an AI assistant write this piece without our data, our tests, our customers, or our product? → If yes, there is no AVI yet.
2. **The logo test.** Could a competitor publish this exact text, changing nothing but the brand name? → If yes, there is no AVI yet.

Both tests are about the piece, not the topic. A well-covered topic can still fail both.

### Step 3 — Locate each AVI type in your draft

#### 01 — Systematization

| | |
|---|---|
| **Question** | Does the reader get a new way to think about the problem? |
| **Counts** | Our own categorization or levels; selection criteria; a decision framework; stages of a process; a comparison matrix we built; a diagram the reader could redraw and reuse |
| **Doesn't count** | A numbered list of tips; a table of contents dressed as a framework; a known model (AIDA, RACE, RFM) retold without adding anything of ours |
| **Proof** | The reader can apply the framework to their own case without rereading the article |
| **In my draft** | Section: ______ |

#### 02 — Unique Knowledge

| | |
|---|---|
| **Question** | Is there information here that only we can provide? |
| **Counts** | Our A/B tests; internal platform statistics; patterns from support and customer success; client results (with permission); our own survey; an experiment that failed; an expert quote we obtained ourselves |
| **Doesn't count** | Someone else's report retold; a number without source, period, and sample; an opinion with no evidence behind it; user-count bragging used as decoration rather than as evidence |
| **Proof** | Every figure carries period + sample + conditions; every story carries a named context |
| **In my draft** | Section: ______ |

#### 03 — Product Mastery

| | |
|---|---|
| **Question** | Can the reader open the product and follow along? |
| **Counts** | Step-by-step instructions with exact UI names; current screenshots; a reusable method or pattern; fallback and edge-case handling; what to verify before sending; known limitations of the approach |
| **Doesn't count** | "Stripo lets you do X"; a feature list; a link to the Help Center instead of the steps; a screenshot with no explanation of the decision behind it |
| **Proof** | A reader with the product open completes the task without guessing a single step |
| **In my draft** | Section: ______ |

### Step 4 — Verdict

VI level = how many AVI types the piece must contain.

| VI level required | You must be able to point to | Verdict if you found fewer |
|-------------------|------------------------------|---------------------------|
| 0 | Nothing — support docs and landing pages only | — |
| 1 | Any 1 of the 3 types | Not ready → Step 5 |
| 2 | Any 2 of the 3 types | Not ready → Step 5 |
| 3 | All 3 types | Not ready → Step 5 |

A type counts only if you can name the section it lives in. "Almost systematized" or "we mention our experience somewhere" is not a type.

### Step 5 — If a type is missing, this is the fastest way to add it

| Missing | Fastest fix | Who to ask |
|---------|------------|-----------|
| Systematization | Turn your flat list into 3–4 groups with a selection criterion, or into levels with a progression logic | Peer review with another writer |
| Unique Knowledge | Pull one number from our own data, or one recurring question from support | Product/BA, support, customer success |
| Product Mastery | Replace the feature mention with the actual steps and one current screenshot | Product team, Help Center |

If none of these is available in time, lower the VI level honestly — publish the piece as what it is, rather than claiming a level it doesn't meet.

### Step 6 — Before you submit

- [ ] Each required AVI type is mapped to a specific section
- [ ] Every number has a source, period, and sample
- [ ] Our own data is explicitly labeled as ours
- [ ] Screenshots match the current UI
- [ ] The piece survives the ChatGPT test and the logo test
